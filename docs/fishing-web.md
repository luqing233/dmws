# 鱼种投稿、审核与事件管理网页

网页集成在现有Spring Boot应用中，入口为 `/`，不需要独立前端服务或访问数据库的浏览器凭据。已于2026-11-15部署生产：`https://fish.luqing.fun/`，应用后端端口8002，对外HTTPS端口443；沿用用户配置的反向代理。

| 入口 | 功能 |
| --- | --- |
| `/#submit` | 所有人可投稿普通鱼、彩蛋鱼、金币/战斗/监狱事件；预览回执并查询进度 |
| `/#catalog` | 查看已经启用的正式鱼种，按名称搜索、分页 |
| `/#review` | 管理员登录后审核投稿、管理现有鱼种、管理特殊事件 |

## 投稿与审核

公开投稿只保存到待审表，不会直接改变正式鱼池。提交后得到查询码，可以复制进度链接；查询只返回该投稿的状态、审核意见及发布结果，不返回审核员账号或投稿人的私人信息。重复请求复用同一投稿，改内容重用请求编号会被拒绝。

管理员可以调整数值、描述或事件文案后通过；驳回必须说明原因。原稿与审核后的资料分别保存。通过操作同时写入正式定义和审核回执，失败整体回滚；两个管理员同时处理同一投稿或同名鱼种时不会重复入池。状态和版本过期时需刷新，不能覆盖他人的审核结果。

鱼种投稿表单范围：名称1～80字、描述1～255字、等级1～101、基础价1～1,000,000、难度0～1000、尺寸1～1,000,000厘米。价格、等级、尺寸与难度均为整数，最小尺寸不得超过最大尺寸。描述支持现有钓鱼占位符，浏览器将正文作为纯文本显示。

预览直接使用现有钓鱼算法和数据库回执模板。鱼种预览展示成功钓获时的尺寸/售价、白饵钓获率及解锁等级，未计自动购饵支出；事件预览分别展示获得/损失金币、战斗胜负和调查结果。预览不会注册玩家、扣款、入院或生成钓获记录。手机端默认收起预览，可按需展开。

## 编辑现有鱼种

在“管理现有鱼种”中按名称查找，编辑名称、描述、等级、价格、难度、尺寸、普通/彩蛋属性和启用状态，再保存。鱼种ID不变，已有渔获的名称、尺寸、成交金额和排行榜快照不会重算。管理员可保留已有的高等级数值，不会被投稿表单的101级限制截断。

内置鱼通过 `fish.seed_name` 记录稳定的种子身份。首次启动仅为匹配的现有内置鱼补齐此标识，不覆盖游戏参数；以后按该标识补缺，管理员改名不会导致重启后又生成一条旧名字的内置鱼。网页只提供停用，不删除历史鱼种。

## 管理特殊事件

普通鱼及彩蛋仍保存在 `fish`；尼罗鳄、尸体等属于独立事件。事件表单按三类显示对应参数：

- 金币：支持包含正负数的闭区间、金额步长，零可作为纯剧情。
- 战斗：敌方武力、奖金上下限、胜利受伤概率、失败轻中重伤分配。
- 监狱：1～30分钟调查/服刑，不额外增加犯罪值。

事件编号创建后固定；名称、分组、抽取权重、启用状态及所有事件专属场景文案均可编辑。左侧分支树随事件类型联动：金币仅显示金币结果，战斗才显示胜负、伤势、电棍与红牛，监狱仅显示调查/服刑。共同开场与描述始终可编辑，鱼饵、欠款及回执布局收在高级设置中。切换类型不会删除原有其他类型文案，它们暂不显示、不触发，切回对应类型后可继续编辑。

点击分支后，右侧显示当前路径、触发条件、实际默认文案及预览；未修改的分支直接继承数据库默认文案，不复制为事件专属记录。选择“基于默认文案编辑”后，才创建可修改的候选句；“恢复默认文案”会停用该分支的专属句子。每个启用场景的总权重必须大于零，描述也可继承有效的全局默认。预览展示第一条启用且正权重的专属候选，实际结算按权重抽取。选择道具分支会自动模拟对应道具，管理页预览也自动刷新；结果按钮与道具复选框取代组合场景长下拉框。

金额以十进制字符串传输，避免浏览器浮点数丢失分值。保存会检查金额步长、伤势比例以及每档鱼饵的总事件票数，防止总概率超过100%。文案编号只能归属于当前事件，不能借修改事件覆盖全局或其他事件的文案。移除的旧文案会停用保留，避免启动补缺时重新启用；迁移备份字段不覆盖。

现有鱼种和事件的保存都校验当前配置指纹。旧页面保存过期版本返回409；相同操作编号的重复提交返回原结果。直接管理修改也会写入一条已通过的审核记录，保存修改前后快照、操作账号和说明。

编辑器保留第一版左侧目录、右侧项目编辑及独立预览。“战斗结果”有成功/失败两个编辑选项；红牛、电棍、住院有通用文案、成功文案、失败文案三个选项，各自独立保存。金币/监狱不会显示战斗项目。

| 项目 | 通用 | 成功专属 | 失败专属 |
| --- | --- | --- | --- |
| 红牛 | `BOOST_RED_BULL` | `BOOST_RED_BULL_WIN` | `BOOST_RED_BULL_LOSS` |
| 电棍 | `BOOST_BATON` | `BOOST_BATON_WIN` | `BOOST_BATON_LOSS` |
| 住院 | `INJURY` | `INJURY_WIN` | `INJURY_LOSS` |
| 结果 | — | `COMBAT_WIN` | `COMBAT_LOSS` |

文案以各条实际顺序中的“战斗结果”为分界：之前的项目只使用通用文案，不显示成功/失败编辑选项；之后的项目才使用对应结果专属文案，未配置时回退通用。两条路径位置不同时，按各自位置开放选项。旧专属文案保留，移回结果之后会恢复生效；停用成功专属不影响失败专属。未改时直接显示继承的默认模板，基于默认编辑才建立专属句子。`{baton_energy}`、`{injury}`、`{injury_score}` 来自真实结算。实际使用道具才显示道具提示，实际受伤才显示住院提示。预览区分获胜未受伤、获胜并住院、失败并住院，并支持红牛/电棍组合；示例电量80/100、胜利轻伤1、失败中伤40，预览不消费道具。

左侧“战斗文案 · 拖动排序”可直接拖动四个项目旁的“↕”，也可用上下按钮或聚焦拖动柄后按上下方向键。排序范围有“同步／成功／失败”：同步拖动统一两条结果路径的顺序，旧的独立顺序保留停用；成功、失败各自排序时不改变另一条路径。只调整顺序，不改写各项目的成功/失败文案。“战斗叙事顺序”项目保留详细编排和恢复默认入口。每次只走实际胜负路径；未使用的道具与未发生的伤势自动跳过。公开投稿中的排序随投稿一起保存，管理员审核后生效；修改正式事件需点击“保存事件配置”。

通用布局使用 `COMBAT_FLOW`，网页编排的成功/失败路径使用 `COMBAT_WIN_FLOW`、`COMBAT_LOSS_FLOW`。`{combat_result}`、`{injury_notice}`、`{red_bull}`、`{baton}` 必须各保留一次；可包含一次不输出文字的 `{branch}` 记录布局边界，但文案分界始终是 `{combat_result}` 的实际位置，其他只允许空白。旧布局仍可使用。恢复默认顺序停用三种专属布局，不删除文案。启动只补缺，不覆盖自定义配置和历史回执，无需新增列。新事件使用空归档描述及运行时事件名回退，防止重启把继承默认描述重新变成专属句子。

## 显示主题

首次访问默认暗色模式，可用页头的“浅色模式／暗色模式”按钮切换，浏览器会记住选择。主题适用于投稿、鱼池图鉴、审核、表单和预览；切换不重置正在编辑的资料。偏好只保存在本机 `localStorage.fishing-theme`，不写入数据库；浏览器禁止存储时仍可在当前页面切换。

## 启用与登录配置

1. 在运行库执行 `scripts/migrate_fishing_web.sql`。脚本新增待审表、目录写锁和内置鱼种身份列；即使暂不开网页，使用JPA validate的新Jar也需要这些结构。
2. 运行 `python scripts/hash_fishing_web_password.py`，交互输入不少于12字符的独立审核密码。脚本只输出PBKDF2哈希，不打印密码。
3. 在Git忽略的实际配置中启用：

```yaml
dmws:
  fishing-web:
    enabled: true
    admin-username: admin
    admin-password-hash: '粘贴脚本输出的完整pbkdf2-sha256哈希'
    session-minutes: 30
```

也可以通过 `DMWS_FISHING_WEB_ADMIN_PASSWORD_HASH` 环境变量覆盖哈希。不要复用MCP Bearer、经济可信消息HMAC密钥或OneBot令牌。空/无效哈希不会开放审核登录。

生产使用HTTPS，并在反向代理保留原始Host；HTTPS部署设置 `server.servlet.session.cookie.secure=true`。登录使用HttpOnly、SameSite=Strict会话Cookie，审核和保存同时校验会话内CSRF令牌；密码不保存到浏览器本地存储。默认30分钟无操作失效，重启后需重新登录。匿名提交、预览及登录有独立频率限制。反向代理下如需按真实访客IP限流，应使用可信代理配置处理转发头，不直接信任客户端X-Forwarded-For。

## 数据与迁移

`economy_fish_submission` 通过 `submission_type` 区分FISH/EVENT；原始鱼种字段或事件JSON、审核后JSON、审核账号/说明、已发布ID/编号、编辑源ID/编号、版本及请求去重字段均持久化。`economy_fish_review_lock` 只串行化目录和审核写入，不锁玩家账户。所有审核与发布都使用同一 `dmwTransactionManager` 事务；不影响既有经济账本和历史归档。

网页修改在后续读取/收竿时生效，已保存回执不变。上线前按现有流程停写备份、恢复副本演练，再迁移和发布；发生过改名后，回退版本也需理解稳定种子身份，避免旧版按名字重新补鱼。
